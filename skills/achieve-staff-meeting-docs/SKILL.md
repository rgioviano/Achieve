# Achieve Staff Meeting Docs

## When
Biweekly Achieve staff meeting (Wed ~2pm CT) agenda in Google Drive, or any edit to that doc’s New Starts / Client Roster sections.

## Create the doc
1. In Achieve Drive, duplicate **Achieve Staff Meeting Template** (or the most recent filled `Staff Meeting - MM.DD.YY` if the template is missing).
2. Name exactly: `Staff Meeting - MM.DD.YY` (example: `Staff Meeting - 11.04.26`). Do not use older “Achieve Staff Meeting …” titles.
3. Before filling, skim 2-3 recent past meeting docs and match their section order, table look, and fill density.
4. Aim to finish before Ryne’s ~1pm CT prep block; send Chief the doc link when solid (bulleted status, no em dashes).
5. Mark unverified items clearly; leave `[Ryne]` for items only he can fill. Do not invent facts.

## Section order (keep)
1. **Wins + Recognition** - Client Win, Coach Callout (and Business Metric only when it belongs that week)
2. **Client Roster Updates** - New Starts, Injuries / Flags, At-Risk / Check-In Needed, Successes to Reinforce
3. **Operations + Housekeeping** - High School Training, Coaching & Programming on Floor, MindBody / Billing, Equipment / Facility, Hawkin / Testing, Lead Gen, Other
4. **In-Service / Teaching Block** (or IB / special topic when that week’s focus) - Topic, Key Points, Discussion Question
5. **Open Floor + Q&A** - standard coach questions + blank Notes lines
6. **Focus for the Week** - one thing
7. **Next Staff Meeting** - next biweekly Wed @ 2pm

## Tables (visual match - locked 2026-11-04)
- **New Starts:** 3 columns - Athlete | Sport | Notes / Flags
- **Injuries / Flags:** 2 columns - Athlete | Issue / Restriction
- Keep **one** table per section (never stack a second New Starts table under the first). Prefer editing rows inside the existing table; if you must rebuild, restyle afterward so it matches.

### Same look across every roster table
All tables in the doc (New Starts, Injuries / Flags, and any other) must match each other and the Template / latest filled meeting doc:
- **Widths:** same total table width; Athlete columns the same width across tables
- **Cell colors:** same header-row shading and same body cell background (copy from Template / prior meeting - do not leave a newly inserted table on Docs default white if the others are shaded)
- **Fonts:** same font family, font size, and weight (header bold vs body) in every cell
- After `insert_table`, always re-apply column widths, header shading, and text styles so the new table is indistinguishable from the existing ones
- When unsure of exact hex / pt values, open the Template or the previous `Staff Meeting - MM.DD.YY` and match those tables exactly rather than inventing a palette

## New Starts - who goes in
- Everyone who **started** (signed / began training) since the **previous** staff meeting (~2 weeks), not only same-week signups.
- Confirm with Tally and Penny when the list is unclear.
- New signups only - **never** upcoming or open evals.
- Do **not** put back-office items coaches don’t need (Quo line switches, internal bot ops, etc.).
- Coaches are on the floor during meeting hours (except Ryne) - no floor-coverage question.

## New Starts - Notes / Flags (locked 2026-11-04)
Columns already carry **name** and **sport**. Notes only:

1. **Age**
2. **Training history** (e.g. training age X months/yrs, no prior training history, or “not listed” if blank on the Assessment)
3. **Specific injuries** - only if present on the Assessment / known flags (omit the line if none)
4. **Specific goals** - only if written on the Assessment (omit if blank)

Pull age / training history / injuries / goals from the Drive Assessment when available.

**Do not put in Notes:** signup package names, “signed 2x/wk…”, Mindbody admin essays, PRI pattern dumps, movement screen laundry lists, goals fluff beyond what the sheet says, or other admin detail coaches don’t need on the floor.

Good example:
`Age 16. Training age 6 months. Prior L kneecap dislocation (basketball); chest/low back tightness. Goals: get stronger, hit ball harder, learn to lift properly`

## Injuries / Flags
Short, coach-actionable restriction language. Carry-overs stay until cleared. Use `[update?]` when status is stale.

## Cite / label
Only state what was confirmed. Label guesses. Prefer sheet wording for injuries and goals.

## After fill
Re-read Client Roster tables: one New Starts table, correct people, notes in the locked four-part style, and **all tables matching** on width, cell colors, fonts, and font sizes.
